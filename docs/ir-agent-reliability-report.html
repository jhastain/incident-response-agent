03Concurrency drill-down

The three questions asked, answered with live evidence — not assumption. Under load, one investigation succeeded with 75 tool calls while two produced zero output; the pattern pointed away from tools and metrics.

Bypass tool calls?

NO

The successful run made 75 normal tool calls; the failures made zero — they never reached the tool stage at all.

Agent metrics?

NO

The failing runs logged 0 tokens — the model produced no output for them. Nothing to measure; they were blocked upstream.

Code problem?

YES — root cause

Logs showed /api/stream_reasoning_engine completing only twice, 11 minutes apart — streams serialized on the single event loop instead of interleaving.

Two distinct failure modes emerged — visible only because the run was repeated:

Type A · deadline overrun 9 of 12

Clean (no error), cut at ~600s, stops at Tier-2 or verification. Correlates with inflated Tier-1 tool counts — known_issues spiked to 11–25 calls (vs ~7 norm). The heaviest scenario (sql) is squeezed most.

Type B · infra recycle 3 of 12

All three cut simultaneously at 378s (run 05). Logs show an instance Shutting down → Started mid-run, no error. Platform-side instance cycling — transient, not a code defect.

05The honest residual

What's solid

Concurrency is fixed and verified: no event-loop wedge, no stream serialization, no cold-start penalty. Each scenario has passed 6/6 concurrently, and a full 3/3 sweep is reproducible. The single-run path is reliable.

What remains at the edge

The two Tier-2-heavy scenarios run right at the fixed ~600s streamQuery deadline. The failing scenario rotates run-to-run — the same code passed and failed the identical scenario at Tier-1=63 and 57 respectively — so it's tool-count inflation stacking with backend latency, noisy rather than a clean threshold. sql (heaviest Tier-2 tail) sits closest to the edge and fails most.

Why the deadline can't just be raised

Verified live and against Google's docs: reasoningEngines expose no timeout field, agents-cli deploy has no timeout flag, and the configurable inferenceTimeout applies to prediction endpoints — a different resource type. The only lever is making heavy scenarios finish faster, which is what the efficiency work did.

06Corrections to the prior handoff
