Key Decisions

Technology Stack & Trade-offs

Each choice was evaluated against alternatives. Here's what we chose and why.

Framework

Google ADK 2.2.0

LlmAgent, SequentialAgent, ParallelAgent, AgentTool, session persistence out of the box. Agents are Python functions — extractable if ADK proves limiting.

Hosting

Cloud Run

1 orchestrator per incident for isolation. Webhook frontend scales independently. Max 3600s timeout with checkpoint/resume for long investigations.

LLM Gateway

Bifrost

Semantic cache, virtual keys with budget caps, MCP tool aggregation. Circuit breaker falls back to direct Vertex AI on gateway failure.

Data Store

Firestore

Firestore Native mode in aiops-dev-project (us-central1). Stores KB, session state, dedup windows. Semantic similarity via Vertex AI Vector Search (Phase 2).

Audience-Aware Output

Role-Based Agent Layer — SRE / CE / DBA

Investigation agents produce raw findings. Role-based agents filter, prioritize, and present those findings for specific audiences.

🛠

SRE Dispatcher

Audience: SRE on-call engineers

Surfaces infrastructure signals: Cloud Run health, scaling events, OOM kills, container restarts, resource utilization, deploy correlation. Prioritizes by blast radius and time-to-impact.

Posts to: Platform-Alerts, Infrastructure channels

👥

CE Dispatcher

Audience: Customer Experience / Support

Surfaces customer-facing impact: affected endpoints, error rates users see, workarounds if known, estimated scope (how many builders affected). Strips internal infrastructure details.

Posts to: Critical Bug, Scrum Escalation channels

🗄

DBA Dispatcher

Audience: Database administrators

Surfaces SQL signals: blocking chains, top CPU queries (ranked by hits × duration), slow traces with full SQL, connection counts, CPU by host. Includes query structure analysis.

Posts to: DBA-specific channels, PagerDuty DBA escalation

Guardrails

15 Non-Negotiable Investigation Rules

Baked into every agent's system prompt. These override any other instruction and prevent the most common LLM failure modes.

1
Facts before hypotheses. Confidence: STRONG EVIDENCE / MODERATE EVIDENCE / WEAK SIGNAL / UNKNOWN. Never use "CONFIRMED."
2
Follow BOTH outlier types. Duration (30-700s = blocking) AND volume (250K hits = CPU exhaustion).
3
Treat each incident independently. Past incidents inform where to start, not the answer.
4
Search ADO first. A bug filed yesterday IS the answer.
5
Per-query, not aggregate. Drill past blocked-resource to find head blocker.
6
Deploy correlation ≠ causation. Prove with code change AND errors only on new revision.
7
Only flag new PRs. Use git merge-base --is-ancestor to verify.
8
Report incrementally. Share findings as each agent completes.
9
All times in CST.
10
Teams = input, not evidence. Verify with metrics before attributing cause.
11
Analyze query structure. Duration = WHAT is slow. Query text = WHY.
12
PubSub: trace the publisher. Consumer failure is the symptom.
13
Stay in lane. Flag cross-domain findings for orchestrator dispatch.
14
Read-only enforcement. Double-enforced: Bifrost allowlists + agent prompts.
15
Exclude self. IR platform services never investigated — prevents feedback loops.
Security & Resilience

Hardened by Adversarial Review

4-perspective red team evaluation (scale, security, cost, operations) identified 16 findings. All critical and high findings are addressed in Phase 1.

Threat Model

VectorMitigation
Prompt injection via alert payloadsPayload sanitizer strips HTML, truncates fields, escapes injection patterns before LLM ingestion
Write tool exposure via MCP wildcardPer-server read-only allowlists replace ["*"]. Datadog: 5/86 tools. ADO: 5/47 tools.
PII in content logsAccess controls on Firestore. 90-day retention. No raw SQL params in findings.
LLM confidence anchoringBanned "CONFIRMED" label. STRONG EVIDENCE is the ceiling.

Resilience Design

Failure ModeMitigation
Container killed mid-investigationAgent Engine Sessions + checkpointing. Resume from last saved finding.
Dedup race across instancesFirestore transactions.
Bifrost gateway downCircuit breaker: 30s of 5xx → fallback to direct Vertex AI (degraded mode).
Self-referential alert loopSelf-exclusion filter: aiops-*-run-ir-* alerts logged but never investigated.
Teams channel spam during storms90s batch window. Max 10 posts/channel/15min. Storm mode aggregation.

Implementation

Phased Rollout

6 phases. Phase 1 is read-only, human-in-the-loop. Each phase has a clear trigger for the next.

Phase 1 — Scaffold & Infrastructure

Repo, ADK project, webhook frontend with payload sanitizer, Firestore collections (incidents, decision_trees), Bifrost tool allowlists, Sentry internal integration, Cloud Run service YAMLs, ADO pipeline.

Phase 2 — Core Agents

Classification agent, historical search, all 16 investigation agents (9 Tier 1, 5 Tier 2, 3 role-based dispatchers), synthesis agent, verification agent, report generator, investigation checkpointing, Bifrost circuit breaker, ADK wiring with Agent Engine Sessions.

Phase 3 — Teams Integration

Entra ID app, Graph API tool, Teams message batching (90s buffer, rate limits, storm mode), orchestrator posting rules, channel polling.

Phase 4 — Deduplication Engine

Firestore-backed dedup (Pass 1 + Pass 2), self-exclusion filter, merge logic.

Phase 5 — Post-Incident & KB

Debrief agent (13 questions via Teams), KB write with embeddings, decision tree updates.

Phase 6 — Deploy & Test

Dev deploy, webhook registration, E2E test, load test (100 concurrent alerts), checkpoint resume test, Teams spam test.

Future Phases

Optimization

Bifrost cache optimization, GCP MCP server, stale-finding refresh, Tier 1 agent consolidation based on KB data.

Phase 3+

Summary

What We're Building

Phase 1 Delivers

  • Automated alert ingestion from 4 sources
  • Two-pass dedup (atomic, race-free)
  • 16 investigation agents (9 Tier 1, 5 Tier 2, verification, 3 role-based dispatchers)
  • Findings posted to Teams (batched)
  • Knowledge base that learns from every incident
  • Read-only. Human-in-the-loop.

Architecture Principles

  • Deterministic agents, not open-ended exploration
  • Functional scope, not tool boundary
  • Hub-and-spoke, not peer-to-peer
  • Double-enforced read-only (gateway + prompt)
  • Checkpoint/resume for resilience
  • Every design choice is reversible
